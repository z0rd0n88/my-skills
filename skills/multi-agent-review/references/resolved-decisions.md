# multi-agent-review — Resolved decisions

> Reference file for [`../SKILL.md`](../SKILL.md) (multi-agent-review). Load this when you need the historical decision log resolving design ambiguities (numbered table, rationale per entry).

## 13. Resolved decisions

| # | Decision | Choice | Rationale |
|---|---|---|---|
| 1 | Directory file-count cap | 50, override via `--max-files <n>` | 50 keeps reviewer briefs within typical context budgets; explicit override beats silent truncation. |
| 2 | Unknown reviewer name | Hard-fail with list of known agents | Failing fast at parse time beats spawning an `Agent` call that errors mid-flight with an opaque message. |
| 3 | `gh` CLI absence (PR target) | Hard-fail with install instructions | The PR branch cannot proceed without `gh`; no manual-paste fallback because diffs are too large to copy by hand. |
| 4 | PR URL parsing | Pass through to `gh pr view` unchanged | `gh` already handles `github.com` URLs, enterprise hosts, and `#<n>` shorthand — re-parsing duplicates work and introduces drift. |
| 5 | Subagent-spawn tool name | `Agent` | Verified against the Claude Code Agent tool schema exposed in this build; `subagent_type` is the parameter name the tool takes. |
| 6 | Reviewer agent discovery | Validate at parse time against `.claude/agents/` + `~/.claude/agents/` | Fail-fast at parse time; see #2. |
| 7 | `--write-to` overwrite | Refuse if exists, allow with `--force`; the *default* path suffixes `-2` instead (amended by #66) | Aligns with `cp`/`mv` defaults for a path the caller typed. Once #66 made a file the default, the original rule became wrong for the default case: a caller who never chose a path cannot act on a refusal, and "same target reviewed twice today" is a normal thing to do, not an error. So the two cases split — an explicit path still refuses, a derived one degrades to a sibling filename. |
| 8 | PR diff size limit | Warn at 100 KB, do not auto-truncate | Truncation would silently degrade review quality; the user can split a megapatch into chunks themselves. |
| 9 | Default roster (user scope) | `architect-reviewer`, `critical-thinking`, `silent-failure-hunter`, `security-reviewer`, `penetration-tester` | Generic multi-perspective coverage: architecture lens, assumptions/critical-thinking, silent-failure hunting, security, and (added 2.1) an attacker-mindset red-team lens in `L-REDTEAM` — see decision #37 for why that is not the same lane as `critical-thinking`'s `L-ADVERSARIAL`. `penetration-tester` is the only entry allowed to be absent from the pool without hard-failing. Override per-invocation via `--reviewers` for domain-specific lenses. |
| 10 | Mode presets | Bring-your-own — put `<name>.md` files under `.claude/multi-agent-review-modes/<name>.md` in a project, or under `<plugin-install-root>/modes/<name>.md` if you fork the plugin to ship defaults. This plugin ships no preset library out of the box; project scope shadows user scope by filename; explicit `--reviewers` / `--synthesizer` still override the preset. | Mirrors the agents/skills/commands "one file with frontmatter" shape so each repo can carry its own preset library without inventing a new config format. Not shipping defaults keeps the plugin opinion-free; the plugin ships the mechanism, not the taxonomy. |
| 11 | `diff` target | `git diff` (working tree) by default; `git diff --staged` with `--staged`; empty diff = hard-fail | Pre-PR reviews target uncommitted code by definition; making this a first-class target removes the "open a draft PR just to review it" anti-pattern. Working tree is the default because that is where unstaged refactors live; `--staged` exists for cases where the user has already curated the commit. |
| 12 | `slices` target | Fan-out reviewer roster across N directories in ONE parallel dispatch; meta-synthesizer attributes findings per slice and surfaces cross-slice patterns; `--max-slices` cap defaults to 6 | The pre-existing per-slice review pattern (invoke this skill once per slice) required N sequential invocations with no cross-slice analysis. Folding it into a single target gives O(1) human invocation, O(N×M) parallel agent work, and a meta-synth that can identify shared patterns — the actual value-add over per-slice review. Cap prevents runaway agent fan-out. |
| 13 | `--prompt-prelude` | File path; injected verbatim as `## PROJECT PRELUDE` into every reviewer + synthesizer brief; 16 KB cap | Projects need a real hook to tell reviewers "do not re-raise findings already tracked in issues #82/#83/#84" or to enforce house terminology. The "paste it into the chat" workaround documented in some project READMEs was not a real mechanism. File-based + size-capped + applied uniformly = reproducible, version-controllable, and bounded. |
| 14 | Default mode on a `pr` target | Loop (review→fix→re-review) by default, entered via a **confirmation gate** (skip with `--yes`); `--no-loop` restores one-shot read-only | The loop is the higher-value default for the mutate-and-re-test cadence a PR affords; one-shot stays one flag away. An implicit loop prompts before it edits/commits/pushes; `--yes` is the explicit consent for unattended runs. Non-`pr` targets are always one-shot (no branch to push fixes to — dir/file/spec/diff/slices have no "apply fix and re-review" cadence). |
| 15 | Opt-out flag name | `--no-loop` | No collision with existing flags; parallels `--no-smoke`; exact inverse of the new default. |
| 16 | Loop-control flags are loop-only | `--max-iterations`/`--high-and-up-only`/`--no-smoke` hard-fail with `--no-loop` or a non-`pr` target | Prevents a caller silently believing a loop-tuning flag took effect on a one-shot run. |
| 17 | `/multi-agent-review-loop` disposition | **Removed outright (no alias)**; all callsites migrated to `multi-agent-review pr <ref>` | One real entrypoint beats maintaining a second skill+command surface forever; the migration is a bounded one-time edit (3 plugins + issue #47 + config), shipped atomically so nothing dangles. (Reversed the earlier permanent-alias call, 2026-07-11.) |
| 18 | Inner self-call recursion guard | The loop's fresh-subagent review pass calls `multi-agent-review pr <ref> --no-loop --in-loop` (the full modern form also carries `--high-cap off --no-write --no-comment` — see #66 and §5B step 2; this row records only the two recursion layers) | Two parser-visible layers: `--no-loop` forces the inner pass one-shot; `--in-loop` makes §5.0's refusal structural even if `--no-loop` were dropped. Without them the default-loop would recurse infinitely. |
| 19 | Version bump | `1.1.0` → `2.0.0` | Default side-effect profile of the primary command flips read-only → mutating; backward-incompatible per semver. |
| 20 | Max iterations default | 3, hard ceiling 8 | Most issues caught in round 1; 3 catches fix follow-ons; > 8 indicates a fundamental disagreement, not a mechanical loop. |
| 21 | Fix step in the coordinator, not a sub-fixer | Coordinator applies fixes inline | Coordinator has project context (which MEDIUMs apply to this PR vs. project-wide; which findings the human author would push back on); a sub-fixer has neither and produces over-eager patches. |
| 22 | LOW findings never iterate | Comment-and-defer | Iterating on LOW is the treadmill failure mode that makes the loop useless. |
| 23 | Regression detection (same-fingerprint twice) | Stop loop, surface to human | Either the fix didn't land or the reviewer is wrong; coordinator can't adjudicate that. |
| 24 | `--high-and-up-only` flag | Opt-in | Some teams want MEDIUM judgment in the loop; some want only CRITICAL/HIGH discipline. Default is "judgment", flag is "discipline". |
| 25 | Inline-fallback round handling | Run the loop, weight disagreements less | The inner skill can't guarantee subagent-of-subagent dispatch; refusing to loop in that case would block the skill on a tooling problem unrelated to its purpose. |
| 26 | Smoke gate trigger | Project-specific touched-path heuristic + `--no-smoke` escape hatch | Always-on smoke makes the loop too expensive; never-on smoke makes connector-loop regressions invisible until merge. Heuristic + opt-out is the middle. |
| 27 | PR comment + follow-up issue at loop end | Always | The PR's review history should reflect what happened; deferred MEDIUMs need a place to live so they aren't forgotten. |
| 28 | Validated-coverage report | Reviewers enumerate confirmed / examined-inconclusive / not-examined with evidence (§7); synthesizer aggregates into a Coverage Report and tags non-engaged reviewers (§8); the loop refuses an empty-coverage APPROVE (§10.3) | Forcing the reviewer to enumerate what it actually validated converts the review from an opinion into a coverage report, and makes a lazy review visible: an empty Confirmed list beside style-only findings means nothing load-bearing was examined — that should block the gate, not silently pass it. The gate is a **nudge plus deterministic cross-checks, not proof** — evidence is self-reported, so the coordinator validates emptiness claims against the changed-file list and may spot-check one citation. Only APPROVE is gated by design: false findings on a NEEDS_CHANGES round self-correct via the §10.3 regression fingerprint, while a false APPROVE is terminal. |

| 29 | Adversarial refutation stage | New stage between fan-out (§5A.5) and synthesis (§5A.6); **on by default**, `--no-adversarial` opts out. **The default was reversed in 3.0.0 — see #46; the stage itself stands unchanged.** | Every prior guard in this skill defended against false negatives (coverage report, engagement check, empty-coverage gate); nothing defended against false positives, and `--high-cap` ranks by count without ever asking whether a finding is true. In loop mode that gap is expensive — §10.3 auto-actions every CRITICAL and HIGH, so a plausible-but-wrong HIGH becomes a real commit pushed to a PR. Default-on because a flag nobody remembers protects nothing, and the loop's auto-fix path is exactly where the protection matters most. |
| 30 | Refutation scope | Every severity, refuter count severity-scaled (3 for CRITICAL/HIGH via `--refuters`, 2 for MEDIUM/LOW) | Scope and cost are separable. Refuting only CRITICAL/HIGH would leave MEDIUMs — which the loop's coordinator-judgment branch acts on — entirely unchallenged. A flat 3-per-finding would put a 30-finding review at 90 agents for no added discrimination on nits. Scaling the count keeps full coverage affordable, and both tiers preserve the same majority arithmetic so no single refuter can delete a finding at any severity. |
| 31 | Refuter diversity by lens, not by agent | One `subagent_type` (`critical-thinking`), differentiated by an assigned attack lens (evidence / scope / reachability / severity / fix) | Perspective diversity is what makes independent samples worth aggregating; redundancy is not. Three identical skeptics fail together on whatever their shared framing misses. Doing it with lenses instead of three distinct skeptic *agents* also removes a dependency on pool composition — the stage works identically in a repo with one agent installed and one with forty. Caps `--refuters` at 5 because there is no sixth distinct lens. |
| 32 | `UNCERTAIN` counts as not-refuted | Ambiguity upholds the finding | Asymmetric costs. A wrongly dropped CRITICAL is terminal and invisible; a wrongly kept finding costs a human one paragraph. Generic verifier fan-outs default uncertainty to *refuted* because they optimize precision; a merge gate needs the opposite bias. Stated explicitly in the refuter brief (§7a) because the default instinct runs the other way. |
| 33 | Drop threshold = strict majority, floor of two | `drop_threshold(R) = max(2, ceil((R+1)/2))`; `k ≥ threshold` drops, `0 < k < threshold` demotes one level, `k = 0` upholds | Requires agreement across *different lenses* before deleting a finding, so one over-confident refuter cannot bury a real CRITICAL. The two correction terms each fix a specific failure of the obvious `ceil(R/2)`: the **floor of 2** stops a single refuter from dropping a MEDIUM at `R=2` (and makes `--refuters 1` structurally drop-proof rather than needing a special case), and the **`R+1`** makes a tied panel at `R=4` contest instead of drop. Demotion for split verdicts keeps contested findings visible while lowering their claim on attention — the honest rendering of "we disagree about whether this is real." |
| 34 | DROPPED findings are rendered, not deleted | Full entry in a **Refuted Findings** section with every refuter's verbatim reasoning, CRITICAL included | "Dropped" is a rendering decision, not a deletion. The audit trail is what makes dropping legitimate: a human who disagrees with a refutation can only overrule it if they can see what the refuters read. Silently removing findings would make this stage strictly more dangerous than not having it. |
| 35 | Loop does not force refutation on or off | Caller's `--adversarial`/`--refuters`/`--max-refuters` forwarded verbatim to every inner pass (flag renamed by #46; the non-forcing rule is unchanged) | Deliberate contrast with `--high-cap`, which the loop pins to `off`. The budget is forced off because demotion *hides* real HIGHs from the iteration gate; refutation removes findings only after they lose an evidence contest, which is what the gate should be measuring. Forcing it on would also override a caller who has a considered reason to skip it. |
| 36 | Refuted findings carried forward as an exclusion list | Coordinator appends drops to the next round's `--prompt-prelude` under a `## REFUTED IN EARLIER ROUNDS` heading | Reviewers are stateless and rediscover dead claims every round, burning refuters on settled questions and inflating finding counts. Reuses the existing `exclusion-list.md` mechanism rather than inventing a second suppression channel. Suppresses repetition, not revision — a claim can be re-raised if the diff changed underneath it, and a previously-dropped fingerprint returning upheld is a reversal to report, not a regression to stop on. |
| 37 | `L-REDTEAM` lane, distinct from `L-ADVERSARIAL` | New signal-activated lane (`penetration-tester` → `security-engineer` → `security-reviewer`), forced whenever any `risk_flag` fires; review teams only; first FORCED lane to yield when the cap binds | `L-ADVERSARIAL` maps to `critical-thinking`, which asks "what is the author assuming?" and returns un-severitied questions. Nothing in the roster asked "how do I break this?" Rebinding `L-ADVERSARIAL` would have destroyed the assumptions lens to get the attacker lens; a separate lane keeps both. Excluded from build teams for the same reason `L-EXPLORE` is — an attacker pass belongs to review, not construction — and that exclusion is stated as a property of the lane, not of the risk-flag trigger, because the repo `FORCE:` and `CLAUDE.md`-invariant forcing paths are unqualified and would otherwise leak it into a 4-slot build team. It yields first under cap pressure **only while another security lane is in the team** — the tempting unconditional form is unsound, because `L-APPSEC` is never FORCED-eligible and only `keys` forces `L-CRYPTO`, so `risk_flags=[money, on-chain, db-migration]` would drop the attacker lens and ship a risk-flagged review with no security coverage at all. Both the build exclusion and the review-only class it belongs to (with `L-EXPLORE`) are stated as lane-class properties rather than per-trigger caveats, since the repo `FORCE:` and `CLAUDE.md`-invariant paths are unqualified as to which lanes they may name. |
| 38 | One agent fills at most one lane | Lane resolution walks past already-assigned candidates. Chain exhaustion **degrades** for an optional lane and **hard-fails** for a FLOOR/FORCED lane — except `L-REDTEAM`, which drops, and `L-WEB3`, which degrades (no shipped agent covers Solana programs). Resolution follows an explicit total order (FLOORS → FORCED by risk priority, unnamed FORCED lanes by name with `L-REDTEAM` last → optional by score, ties by lane name) | `L-APPSEC`, `L-CRYPTO`, and `L-REDTEAM` all end in `security-reviewer`; `L-DATA` and `L-LANG:sql` both end in `postgres-pro`. A naive walk ships an N-lane team with N-1 distinct agents — a pre-existing latent risk that a third overlapping chain made likely enough to fix. Splitting exhaustion by lane class is required to avoid contradicting `context-aware-selection.md` §6 ("FORCED lanes hard-fail, they don't silently degrade"), which governs exhaustion-by-assignment exactly as it governs exhaustion-by-absence. The total order is not optional polish: the dedup rule is order-dependent, so without a pinned order two runs over an identical diff and pool could award a shared-tail agent to different lanes, falsifying §7's determinism guarantee. |
| 39 | Version bump for refutation | `2.0.0` → `2.1.0` (minor, not major) | Additive: no existing flag changes meaning, no default side-effect profile flips, and `--no-adversarial` reproduces 2.0 output exactly. Report *shape* changes (new section, new tags) and agent cost rises, but neither is a backward-incompatible interface change under semver. Contrast decision #19, which was major because the primary command went read-only → mutating. |
| 40 | MEDIUM/LOW lens pair is signal-dependent | `evidence + reachability` when any `risk_flag` fired; `evidence + scope` otherwise; unknown signals take the reachability pair | A fixed pair optimizes for the wrong false positive half the time. On a risk-flagged diff the scope lens is near-dead weight — a finding against code that moves money or touches keys is essentially always in scope, so that slot returns UPHELD without discriminating; reachability is the live question. Off the risk path the reverse holds: nothing dangerous is reachable either way, and the common false positive is the pre-existing pattern or project convention filed as a defect, which only scope catches. Keyed to the `risk_flags[]` the selector already extracts (`context-aware-selection.md` §4) rather than a second per-finding classifier — reusing an existing observable predicate keeps it deterministic and adds no model judgment. Costs zero extra agents: it swaps slot two, never adds a third. Ambiguity defaults to reachability because a missed reachable vulnerability outranks a surviving out-of-scope nit. |
| 41 | One-shot runs dispatch an orchestrator subagent by default | On for **every** target; `--inline` opts out; the loop coordinator is never dispatched | The refutation stage made the old locus untenable: reviewers + up to `--max-refuters` refuters + a synthesizer all return into whatever context runs them, so an inline run puts ~50 worker transcripts into the caller's conversation to deliver one report. Loop mode already solved this per round (§10.2); one-shot never did. Applied to every target rather than a size/type threshold because a threshold makes callers guess which context they are in, and the saving on a small target is small but never negative. The loop coordinator stays inline because it mutates and its confirmation gate needs a human. |
| 42 | Orchestrator returns a summary and the report file, or the full report when there is no file | With a file: title, Executive Summary, counts, failed roster and path; the integrity check runs on the file. Without one: complete synthesized document, verbatim | Changed in 2.3: a full report in the caller's context cost more than the caller needed, and the file keeps every finding, so nothing is lost. The no-file case keeps the original reasoning. A subagent's default instinct is to compress its return, so the brief states the contract as a shape (starts with `# Multi-Agent Review:`, ends with the final section, nothing around it) rather than as a "do not summarize" prohibition, per the failure-form guidance: prohibitions invite negotiation under a competing incentive, recipes do not. The caller-side check exists because the contract can still be violated and an abridged report is indistinguishable from a complete one to a reader who never saw the original. |
| 43 | Dispatch recursion guard mirrors the loop's | `--inline` (belt) + `--in-subagent` (suspenders), and `--in-loop` also forces `inline` | Same two-parser-visible-token design as decision #18, for the same reason: a default that spawns a subagent will recurse infinitely if the inner call re-enters the same decision. The third condition is the novel part — a loop round is already layer 1, so without `--in-loop` forcing inline the stack becomes caller → round → orchestrator → workers. That matters because the harness does not guarantee subagent-of-subagent dispatch, so depth is not free; it is the very precondition §10.2 step 3 was written to catch. |
| 44 | Depth failure degrades loudly, never silently | Orchestrator returns `DISPATCH-FAILED: …`; caller re-runs inline with a one-line note and refuses any report from that subagent. **Self-reported, not enforced** — backed by two collapse tells (empty Reviewer Disagreements with all reviewers engaged; refutation totals implausible for the settings), neither conclusive | The silent failure is the dangerous one: an orchestrator that cannot spawn workers can still *write a review*, and a single agent imitating five lenses produces something with the shape of multi-perspective review and none of its independence — with refuters that share an author with the findings, which is worse than skipping refutation. §10.2 step 3 already established this pattern for loop rounds; extending it keeps the two dispatch sites from having different integrity guarantees. The residual risk is stated rather than hidden: the caller has no channel to observe a subagent's tool calls, so a fabricated report passes the structural check. Claiming enforcement here would be the same false-confidence error decision #28 avoids for coverage evidence. |
| 45 | Version bump for orchestrator dispatch | `2.1.0` → `2.2.0` (minor) | The *locus* of execution changes; the observable artifact does not — same report, same sections, verbatim. `--inline` reproduces 2.1 behavior exactly. No flag changes meaning and no side-effect profile flips, so it is additive under semver, same reasoning as #39. |
| 46 | **Refutation is opt-in, not default-on** (reverses #29's default) | `--adversarial` enables the stage; default is off. `--no-adversarial` retained as an accepted no-op | Measured, not assumed. After #29 shipped default-on, the median review session went **10.0M → 43.2M billable tokens (~4.3×)**, subagent share **59% → 84%**, and refuters alone consumed **57.8% of all subagent tokens** at ~**0.38M each**; one session dispatched **163** of them. #29's own argument — "a flag nobody remembers protects nothing" — is sound only where the protection is load-bearing, and it is load-bearing in exactly one place: the §10.3 auto-fix path, where a false HIGH becomes a commit with no human in between. On a read-only report the reader is already the refuter, so the stage was paying 4× to pre-filter a list a human was about to read anyway. Opt-in keeps the guarantee available and stops charging for it by default. The recommendation note on unattended `--yes` loops (§4) is the compromise with #29: the case it was written for still gets prompted, without every `dir` sweep paying for it. |
| 47 | Tuning flags require `--adversarial`, and never imply it | `--refuters`/`--max-refuters` without `--adversarial` is a parse-time hard-fail; `--adversarial` + `--no-adversarial` is also a hard-fail | Preserves the pre-3.0 rule's intent (#29-era: never let a caller believe refutation ran with their settings when it did not run at all) in the direction the reversed default makes likely. Implying `--adversarial` from a tuning flag was rejected: inferring a 4× stage from what reads like a knob is exactly the cost surprise the opt-in default exists to prevent, and it would make `--max-refuters 20` — a flag whose plain meaning is *spend less* — silently turn on the expensive path. The contradictory-pair fail follows the same rule: both silent resolutions are wrong in an expensive direction. |
| 48 | Version bump for the opt-in reversal | `2.2.0` → `3.0.0` (**major**) | A default flips, which #39 and #45 both named as the line between minor and major: those were additive because no default side-effect profile changed and the old flag reproduced old output exactly. Here the observable default output changes shape (no refutation tags, no `## Refuted Findings` section, no refutation arithmetic), the default cost profile changes by ~4×, and a bare `multi-agent-review pr 42` behaves differently than it did in 2.2. Same reasoning as #19, which went major when the primary command turned read-only → mutating. `--adversarial` reproduces 2.2 behavior exactly, which makes the migration one flag, but a one-flag migration is still a migration. |
| 49 | `--max-refuters` is per pass, documented as such | Budget is not aggregated across loop rounds; §4 and the flag table both state the `N × --max-refuters` total | Observed in practice before it was documented: a single session dispatched 163 refuters against what was then a "default 60" budget (lowered to 20 by #50), because the loop forwards the budget verbatim to each round and it was never a session-level cap. Per-pass is the correct semantics — each round is an independent review and must be independently verified — so the fix is documentation and a worked total (`--max-iterations × --max-refuters`), not a behavior change. Leaving it implicit made a stated default read as a guarantee it never gave. |
| 50 | `--max-refuters` default lowered `60` → `20` | Same degradation rule, lower ceiling; raise the flag when a run needs full coverage | A live 3.0 verification run made the old default's shape concrete: a 135-line single file produced **13 finding groups → 28 planned refuters**, of which **22 (79%) were for MEDIUM/LOW**. At 60 the budget never binds on a target that size, so a routine one-file review would have spawned all 28. 20 is ~2 dispatch turns at the 16-per-turn ceiling and covers 8–10 findings, which fits the common review. **The known cost is a larger `UNVERIFIED` tail** — degradation now starts sooner, and it skips the *most-corroborated* groups first (step 2), so what goes unchallenged is chosen by budget arithmetic rather than by importance. That was accepted deliberately over the narrower alternative (refuting CRITICAL/HIGH only, which would have cut the same run to 6 with no tail at all) because it keeps every severity eligible for challenge and changes exactly one number instead of reopening #30's scope decision. The mitigation is disclosure, not silence: §4 and §8 both require the arithmetic in the Executive Summary so an `UNVERIFIED` count is never read as a validated one. |
| 51 | Refuter lenses map to named `thinking-skills` techniques | Technique column in §5A.5a step 3; `{{LENS_SKILL}}` in §7a. evidence→`map-territory`, scope→`kepner-tregoe`, reachability→`red-team` (risk-flagged) or `thought-experiment`, severity→`second-order`, fix→`via-negativa` | A one-line lens description tells a refuter *what* to attack but not *how*, leaving it to improvise a method per finding. Each mapped skill supplies an actual procedure for that specific attack. Mapped per-lens rather than per-finding to keep dispatch deterministic. Reachability splits on `risk_flags[]` because `red-team` self-scopes to security/correctness and returns little on a non-risk finding, where walking a consequence chain discriminates better. **Strictly optional**: `thinking-skills` is a separate plugin and not a declared dependency, so the lens question stays authoritative and a missing skill is explicitly forbidden from producing `UNCERTAIN` — since `UNCERTAIN` upholds (#32), that would convert an uninstalled plugin into a silent bias toward keeping findings. |
| 52 | Report adversary stage (§5A.6a), on by default | One agent between synthesis and print; audits the report against reviewer outputs + refutation verdicts; appends `## Report Audit`; `--no-report-audit` opts out | Refutation (#29) attacks findings against the code. Nothing attacked the *report* against its own inputs, yet §5A.6 is where dedupe, the severity budget, refutation-outcome application, and Executive Summary composition all happen — every defect in that list is created after the last reviewer finishes and is invisible to every earlier check. Placed after synthesis because the artifact does not exist before it, and before print because the orchestrator must return one document (#42). Default-on despite #46 making refutation opt-in: the costs are not comparable — refutation scales with finding count, this is exactly one agent per pass regardless of report size. |
| 53 | The audit appends, never edits | Synthesized body relayed unchanged; audit is a separate appended section; advisory only, never blocks | An auditor with edit rights silently becomes a second synthesizer, and #42's verbatim guarantee — the thing that makes the relayed report trustworthy — would no longer hold. Append-only keeps both properties: the reader sees exactly what the synthesizer wrote *and* what an adversary thinks is wrong with it, and can overrule the auditor as easily as the synthesizer. Non-blocking for the same reason a failed advisory check must not consume a completed review. In loop mode the coordinator reads audit items but never actions them (§10.3 step 0); actioning one would mean editing source in response to a complaint about a document. |
| 54 | Nothing audits the auditor | Single pass, no loop, no meta-audit | The regress is real and has no natural stop. One pass catches the mechanical synthesis defects that motivated the stage; a second-order auditor would cost another agent to check prose about prose, with each layer less grounded in anything verifiable than the last. Bounded deliberately rather than left to discover its own limit. |
| 55 | Version bump for lens techniques + report adversary | Skill `3.0.0` → `3.1.0` (minor); plugin `1.11.0` → `1.12.0` | Purely additive: no existing flag changes meaning, no existing default flips, and `--no-report-audit` reproduces 3.0 output exactly. The report gains a section and a run gains one agent — the same profile #39 judged minor when refutation added a section, tags, and cost. Contrast #48, which was major because a default *flipped*; nothing here reverses a prior choice. **The plugin bump lands on `1.12.0`, not `1.11.0`:** this branch was authored against plugin `1.10.0` and independently claimed `1.11.0`, which PR #57 (spec-tacular Phase 4b) took first. Because both sides wrote the *identical* string, the rebase produced **no conflict** — the collision is invisible to git and can only be caught by reading. Any branch bumping the shared plugin version must re-check it against `main` immediately before merge; "merges clean" is not evidence the version is free. |

| 56 | Per-finding fix checkpoint replaces the round-level revert | Apply → test → revert **one finding at a time** (§10.4 step 4); batching is a latency optimization that never widens the revert scope | The old shape applied every fix, tested once, and on failure reverted every touched path and stopped the loop. One bad MEDIUM patch therefore discarded the round's other fixes *and* ended the run, and because the edits were interleaved the coordinator could not say which fix caused the regression — the human restarted from nothing with no attribution. Per-finding checkpointing costs N test runs instead of 1 (bounded by batching disjoint module scopes) and buys both properties back. ## Design evidence (external sources)

Why the current structure and defaults are shaped as they are, beyond this repo's own measurements. Refutation-specific evidence lives in [`adversarial-rationale.md`](adversarial-rationale.md).

| Design choice | Evidence | Source |
|---|---|---|
| SKILL.md is an index under 2,000 words; detail sits one level deep behind a load map | Keep SKILL.md under 500 lines, reference files one level deep, and load detail only when needed; the context window is a shared budget | Anthropic, [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) |
| Hard rules come first | Models use information at the start or end of a long input best and in the middle worst | Liu et al., [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/), TACL 2024 |
| Third-person description, mirrored in `commands/multi-agent-review.md` | The description is injected into the system prompt, and a mixed point of view hurts discovery. The skill listing shows the command's description when both exist (observed 2026-09-29), so the two must match | Anthropic best practices (above) |
| Workflow as a checklist; one term per concept (`roundShapes`) | Checklists for complex workflows; consistent terminology | Anthropic best practices (above) |
| No time-sensitive history in SKILL.md | Move superseded behaviour out of the main instructions | Anthropic best practices (above) |
| Reviewers dispatched in one message | Parallel subagents and parallel tool calls cut research time by up to 90% | Anthropic, [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (Jun 2025) |
| One-shot runs dispatch an orchestrator subagent | Multi-agent runs use about 15× the tokens of chat, so keeping worker transcripts out of the caller's context is the main cost lever | Multi-agent research system (above) |
| Loop defaults to 1 round | An evaluator-optimizer loop fits only when iteration gives measurable value; this skill's rounds measured as non-converging | Anthropic, [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) (Dec 2024); `loop_metrics.py` |
| A fix counts only when a verifier positively confirms it | Missing, incomplete, or incorrect verification is one of three top-level multi-agent failure categories, and verifiers tend to check superficially | Cemri et al., [Why Do Multi-Agent LLM Systems Fail?](https://arxiv.org/abs/2503.13657), NeurIPS 2025 |
