# multi-agent-review — Error handling

> Reference file for [`../SKILL.md`](../SKILL.md) (multi-agent-review): the full table of hard-fail / warn / degrade conditions and their exact messages.

## 11. Error handling

| Condition | Action |
|---|---|
| Missing or invalid `<target-type>` | Hard-fail with a one-line usage summary. Do not spawn agents. On empty args, first run `gh pr view --json number`; if the current branch has a PR, offer `pr <N> --no-loop --no-comment` as a proposal only (never auto-run), else print the usage line. |
| `gh` not on PATH and target is `pr` | Hard-fail with: `gh CLI is required for PR review. Install: https://cli.github.com/`. |
| `gh pr diff` fails or returns empty | Hard-fail with the `gh` error output (stderr) — do not proceed with an empty materials block. |
| Loop-only flag (`--max-iterations`/`--high-and-up-only`/`--no-smoke`/`--resume-stopped`) combined with `--no-loop` or a non-`pr` target | Parse-time hard-fail with a clear message (e.g. `--max-iterations is only valid on a looping pr target; it conflicts with --no-loop`). |
| Default-loop precondition unmet (no worktree on `headRefName`) | Hard-fail: `multi-agent-review loops by default on a PR and needs a worktree on <headRefName>. Create one, or pass --no-loop for a one-shot read-only report.` Never guess a branch to mutate. |
| PR `state != OPEN` in loop mode | Hard-fail — closed/merged PRs can't be iterated. |
| Confirmation gate reached non-interactively without `--yes` | Hard-fail with `multi-agent-review pr loops by default and needs confirmation; pass --yes to run unattended` — never hang on an unanswerable prompt. |
| Confirmation gate declined interactively | Abort the loop cleanly, no mutation; suggest `--no-loop` for a read-only report. |
| Recursion guard | The loop's inner self-call must carry `--no-loop` **and** `--in-loop`; §5.0 reads the parser-visible `--in-loop` token from its own `args` and forces `oneshot` when present — the structural backstop even if `--no-loop` were dropped. |
| `--high-cap <n>` passed on a looping `pr` target | Warn that it is overridden to `off`; do not silently drop it. Reason and scope: §4 "Loop defaults" in `defaults.md`. |
| Inner self-call fails to resolve (loop round) | Retry once with the PR URL form (still carrying `--no-loop --in-loop --high-cap off --no-write --no-comment` — the artifact suppressors are not optional on the fallback form either, or the retried round writes its own file and comments); if both fail, list the inner skill's installed location and stop the loop. |
| `dir` target path does not exist or is not a directory | Hard-fail with the missing/invalid path; do not run `git ls-files` against it (which would silently emit empty output and produce a vacuous review). |
| Directory has > `--max-files` files | Hard-fail with the count, the cap, and the override flag (`--max-files <n>`). |
| `file` target has more than one path | Hard-fail. Tell the user: for multiple files use `dir <shared-directory>` if they share a directory, otherwise issue separate `file` invocations. `spec` is only for multiple markdown specification documents — do not suggest it for non-markdown file sets. |
| Path doesn't exist (`file` or `spec`) | Hard-fail with the missing path; do not silently skip. |
| Unknown reviewer or synthesizer name | Hard-fail before any agent is spawned, with the union of known names from `.claude/agents/` and `~/.claude/agents/`. |
| `--write-to` destination exists, no `--force` | Hard-fail in §5A.1 step 10, BEFORE any reviewer agent is spawned (don't waste N agent calls). Applies to an explicitly chosen path only — a *default*-path collision suffixes `-2` instead, since the caller cannot act on a refusal for a path they never typed. |
| `--write-to` and `--no-write` both passed | Hard-fail at parse time: `--write-to and --no-write are mutually exclusive`. Zero agents spawned. |
| Report write fails (permissions, read-only FS, full disk) | Print the report to stdout in full, with a one-line stderr note naming the path and the error. Never discard a completed review over a failed write. |
| `--no-comment` on a non-`pr` target | Accepted no-op; no warning. There is no comment to suppress. |
| `--no-write` and `--no-comment` both passed on a `pr` target | Proceed, but note on stderr that the run will leave no durable artifact at all — the caller has opted out of both, which is legal but deliberately hard to reach by accident (#66). |
| Derived slug normalizes to empty or a bare `-` | Fall back to `<target-type>-review`. Never abort a completed review over its filename. |
| Default path still taken after `-20` | Append `$(date +%H%M%S)` instead of continuing the search. |
| **Rostered reviewer refused at spawn** | **Same rule as the lens-slot row below — the carve-out that used to exempt code reviewers is withdrawn.** Re-dispatch the refused reviewers once, in a second single-message batch after the first returns; if any is still refused, hard-fail the run and emit no report, naming each. |
| **Rostered reviewer accepted the dispatch and never returned** | **Hard-fail at §5A.5's reconciliation** (`returned < dispatched`). Name each missing reviewer and slice. Do not synthesize around the hole and do not re-run only the missing lanes — dedupe and the severity budget are computed over the whole set. This is the shape a backgrounded worker produces; fix the dispatch. |
| Reviewer returns successfully but with empty output | Count it as returned (the reconciliation passes — the lane ran), write `<reviewer-name>: [FAILED — no output]` into the synthesizer brief, and continue. The synthesizer flags it under "Reviewer Disagreements" and the Coverage Report shows the lane as uncovered. |
| **Lens slot refused at spawn** (`Concurrent subagent limit reached`, or any dispatch rejection) | **Re-dispatch the refused lens slots once**, in a second single-message batch, after the first batch returns — the roster returning is what frees the session-wide slots, so this is not a retry against unchanged conditions. Exactly one re-dispatch, no backoff loop. **If any lens slot is still refused, hard-fail the run and emit no report**: `--lenses requested <slugs>; <n> could not spawn (<slugs>). Re-run with fewer concurrent agents.` A zero-lens report is shaped exactly like a normal review, so continuing reproduces the silent no-op the feature exists to remove (§5A.4). |
| Computed dispatch width `(N + L) × M` exceeds the harness's concurrent-subagent cap | Parse-time hard-fail (§5A.1) naming the computed width, the cap, and the flags that reduce it (`--max-slices`, fewer `--lenses`, `--reviewers`). The cap is **session-wide and shared with every other running agent**, so the usable budget is smaller than the nominal limit and unknowable at authoring time. Do not discover the ceiling one refused `Agent` call at a time. |
| §5A.5 reconciliation shows `returned > dispatched` | Hard-fail. Output is arriving from something this pass did not dispatch — most likely a previous run's background children notifying the top-level session and landing in this turn. |
| Round report shows `Reviewers: <returned>/<dispatched>` with the two numbers unequal | **The reconciliation gate's primary trigger** (§10.3 step 0b). Stop with `STOPPED_DISPATCH_UNAVAILABLE`, naming the round and both numbers. Runs on every round regardless of verdict — a NEEDS_CHANGES round drives commits, so gating only APPROVE would leave the mutating path unchecked. Do not re-dispatch to paper over it. |
| Round report is missing the `Reviewers: <returned>/<dispatched> returned` line | **Absence fails, never passes.** Stop with `STOPPED_ROUND_UNUSABLE` — not `STOPPED_DISPATCH_UNAVAILABLE`, which would misdescribe the cause. The usual cause is an **older installed skill** predating §5A.5's reconciliation: the inner pass resolves to the installed plugin, not the working tree, so this is the normal mid-rollout state and the human's fix is to update the plugin, not to debug dispatch. |
| Round subagent returns `ROUND-FAILED: <reason>` (loop mode) | The inner one-shot pass hard-failed and emitted no report (§5A.4 refused reviewer, §5A.5 reconciliation, or a §11 parse-time fail). Stop with `STOPPED_ROUND_UNUSABLE`, carrying `<reason>` verbatim into §10.7. Do not re-dispatch and do not infer a verdict from whatever findings were visible before the hard-fail — they came from an incomplete fan-out, which is why the pass refused to synthesize them. |
| Round subagent returns anything that is not the §10.2 schema and not a sentinel (prose, partial schema, a summary, a verdict with no `## Coverage` block) | Stop with `STOPPED_ROUND_UNUSABLE`, reason `unparseable round return`. **Do not repair, infer, or re-dispatch** — a subagent that returned the wrong shape has demonstrated it is not following §10.2, and a degraded report is indistinguishable from a fabricated one. A missing report is recoverable; a fabricated one is not. |
| Round subagent returns `DISPATCH-FAILED: Agent tool unavailable in subagent context` (loop mode) | Stop the loop with `STOPPED_DISPATCH_UNAVAILABLE`, name the round, surface to the human. **Do not fall back to running the reviewer lanes inline** — that path is withdrawn (§10.2 step 3). Do not retry. |
| Synthesizer fails | Print: `Synthesizer <name> failed. Reviewer outputs follow:` then dump each reviewer's verbatim output with delimiters. If a report path was set (the default), write the same content to that path with a leading header noting the synth failure (see §5A.7). |
| PR diff > 100 KB | Emit a warning to stderr (`warning: PR diff is <n>KB; reviewers may truncate`) and proceed. Do NOT auto-truncate. |
| `diff` target outside a git repo | Hard-fail: `diff target requires a git repository (cwd: <pwd>)`. |
| `diff` target has empty diff | Hard-fail: `diff target has no working-tree changes` (or `… no staged hunks` when `--staged`). Do not proceed with empty materials. |
| `--staged` without `diff` target | Hard-fail at parse time: `--staged is only valid with the diff target`. |
| `slices` with fewer than 2 paths | Hard-fail at parse time: `slices target requires at least two directory paths; use 'dir' for a single directory`. |
| `slices` exceeds `--max-slices` | Hard-fail with the count, the cap, and the `--max-slices <n>` override flag. Default cap 6 keeps the agent-fanout (N × M) bounded; lift it deliberately, not accidentally. |
| roster × slices exceeds **16** | Hard-fail naming both numbers and the product, and suggest either fewer slices or an explicit `--reviewers` list. 6 reviewers × 6 slices is 36 agents in one message, against a `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` of 16 — the excess queues rather than fails, so the run silently becomes three sequential waves while still claiming to be one parallel dispatch. 16 is the same ceiling `total-review` already imposes on itself. |
| `--prompt-prelude` path missing | Hard-fail: `--prompt-prelude file not found: <abs-path>`. |
| `--prompt-prelude` > 16 KB | Hard-fail: `--prompt-prelude file is <n>KB; cap is 16KB. Split or trim it.` |
| Test regression on one fix's checkpoint (loop round) | Revert **only that finding's changes** by restoring §10.4 step 3's `preDispatchBlobs` — **never `git checkout -- <paths>`**, which restores from the index (a no-op if the applier staged) and discards every earlier finding's hunks in a shared file, which the serial path exists to handle. Record `REGRESSED` with the failing output, continue the round with the remaining findings (§10.4 step 4). Do **not** revert the round and do **not** stop the loop for one fix. |
| `loop-state.json` exists but `loop_state.py check` prints `STALE <reason>` (§10.1) | Rename it to `loop-state.stale-<epoch>.json`, note the reason once, start a fresh loop. Never resume from a state whose recorded head does not **exactly match** current `HEAD` — commits landed since the checkpoint can change what a `verifiedFixed` or `refuted` entry still claims is settled, so an ancestor relationship is not enough. |
| `loop_state.py check` prints `STALE remote PR head ...` (§10.1) | The PR branch moved since the checkpoint (a force-push or a fast-forward by another actor), so the checkpoint describes code the PR no longer has. Same handling as any other `STALE`: rename the file and start a fresh loop against the current head. Never resume by dropping `--remote-head` to make the check pass. |
| `loop_state.py check` prints `STALE prior_findings_fingerprints missing` (§10.1) | Same handling as any other `STALE`. The checkpoint was written after a completed round but carries no regression-detection history, so a resumed round would treat a recurring finding as new and mutate again instead of stopping for a human. |
| `loop_state.py check` prints `STALE working tree or index is dirty ...` (§10.1) | An interrupted round left uncommitted edits: HEAD matches the checkpoint, the local tree, and the remote, yet an applier's work is still in the index or the working tree. **Untracked files count** — everything except the state file's own checkpoint directory — because an applier that creates a new source or test file and dies before staging it leaves every head matching and nothing tracked dirty. Do **not** resume — the next finding's `git add` would commit it under a message that never mentions it. Inspect the paths, commit or discard them by hand, then start a fresh loop. Never clear them with `git checkout -- .`; the tree may hold a fix worth keeping. |
| `loop_state.py check` prints `COMPLETE approved at round <n>` (§10.1) | The loop ended on an accepted APPROVE (§10.3 step 1), which is terminal. Report the checkpoint's final state and stop. A further review is a fresh loop, never a resume — resuming would re-review, re-fix, and re-push a round the loop already settled. |
| `loop_state.py render-prelude` exits 2 with `rendered prelude is <n> bytes; cap is 16384` (§10.2 step 0) | The render is over the `--prompt-prelude` cap and nothing was written. **Do not dispatch the round** — the inner pass hard-fails on an oversized prelude, and this refusal is deliberately placed before the dispatch so the failure costs no round. Drop `files opened` lists oldest-round-first until it fits, re-render, and only then build the step-1 brief. Never drop the verifier block to make room. |
| `loop-state.json` exists but `loop_state.py check` prints `COMPLETE <reason>` (§10.1) | The loop already spent its `max_iterations`; there is no round to resume. Report the checkpoint's final state and stop — a further round is a **fresh loop with a new budget** (`--max-iterations <n>`), never a resume that silently overruns the cap the caller set. |
| `loop-state.json` exists but `loop_state.py check` prints `STOPPED <reason>` (§10.1) | The last round ended on a safety stop (§10.6), not an interruption. Do not resume automatically. Surface `<reason>` to the human and only re-run with `--resume-stopped` (the public looping-`pr` flag, §3) after they judge it safe to continue past that specific stop; absent that judgment, start a fresh loop instead. The coordinator forwards it to `loop_state.py check` only. |
| `loop-state.json` or `prelude-round-<N>.md` cannot be written (§10.5 step 7, §10.2 step 0) | Note once and continue the round — checkpointing never stops a loop — but say explicitly that the next round carries no state and the loop cannot resume if the session dies. A prelude that cannot be written means round N runs with the caller's prelude alone; record `prelude-missing r<N>` in the round note. |
| Round return has no `## Shape` block (§10.3 step 5) | Formatting failure, not a gate failure: record `{roster: unknown, axes: unknown}` in `roundShapes`, note `shape-missing r<N>`, continue. The next round still rotates by stating its own shape. |
| Smoke failure on a loop round | Revert every surviving fix that touched a smoke-covered path, record each `REGRESSED`, keep the fixes that touched none (§10.4 step 6). |
| Every fix in a round ended `REGRESSED`/`FIX_FAILED` | STOP with `STOPPED_NO_FIX_LANDED` — nothing is pushable and the next round re-derives the same findings against the same code (§10.6). **Count only round-fatal `FIX_FAILED`s**: a round whose sole non-landing outcome is `FIX_FAILED (unverified)` continues, or §10.6's carve-out is defeated on exactly the 1–3-finding round #69 exists for. |
| A dispatched applier committed, staged, or pushed (§10.4 step 3 / §10.4a step 3) | **Pushed → STOP with `STOPPED_APPLIER_PUSHED`** (§10.6); the coordinator cannot un-push. **Committed →** measure `git diff --name-only preDispatchSha <moved-HEAD>`; within the owned set, `git reset --mixed` (never `--soft`, which leaves everything staged for §10.5's next commit), restore `preDispatchBlobs`, record `scope violation (committed)`, fall back to the coordinator's edit; **exceeding the owned set → STOP with `STOPPED_APPLIER_ESCAPED_SCOPE`** (§10.6) — the coordinator holds no snapshot for paths it never granted, so it can neither prove nor undo what changed. **Staged →** unstage the additions before anything else. On the parallel path, a **committed-within-owned-set** or **staged** violation fails the whole batch back to serial re-application — restoring the batch `preDispatchBlobs` and `preDispatchTestBlobs` first, since serial re-application would otherwise snapshot the tampered state as its baseline — because with one shared tree the offender is not attributable and a moved HEAD invalidates every applier's measurement. **A push, or a commit exceeding the owned set, stays loop-fatal on the parallel path exactly as on the serial path** (`STOPPED_APPLIER_PUSHED` / `STOPPED_APPLIER_ESCAPED_SCOPE`). |
| The round's push fails for any reason — lease refused, branch rewound or deleted, network (§10.5 step 5) | STOP with `STOPPED_REMOTE_HEAD_MOVED` (§10.6) — the `--force-with-lease=<branch>:<roundStartOid>` push is the guard, so a nonzero exit means the branch is no longer the one the round reviewed, or cannot be shown to be. **Do not retry, do not re-push with `--force`, do not fetch/rebase/merge to reconcile.** Write `stateFile` with `stop_reason: STOPPED_REMOTE_HEAD_MOVED`, both OIDs (round start, current head), and the push's stderr before exiting, then surface to the human. |
| `loop-state.json` is unparseable JSON — `check` prints `STALE checkpoint is corrupt (...)`; `stamp` / `render-prelude` exit 2 with the same text and no traceback | A write was interrupted before the atomic rename landed, or the file was hand-edited. Same handling as any other `STALE`: rename it to `loop-state.stale-<epoch>.json` and start a fresh loop. The checkpoint directory's per-round `round-<N>.json` files survive, so a human can still see what the loop had. **Never hand-repair the JSON to make a resume possible** — a checkpoint you patched is not one the loop wrote, and the resume it enables trusts scope nothing verified. |
| A CRITICAL's fix ended `REGRESSED`/`FIX_FAILED` | STOP with `STOPPED_CRITICAL_UNFIXABLE` (§10.6). Never push lower-severity fixes on top of an unresolved CRITICAL. **Except `FIX_FAILED (unverified)`** — see §10.6's qualifier carve-out: a verifier that crashed rendered no judgment about the code, so it reverts and surfaces but does not stop the round. Every other qualifier is fatal, including one not listed there. |
| Parallel applier edited a file it did not own (§10.4a step 3) | Revert that finding's paths, record `REGRESSED (scope violation)`, re-apply it with the coordinator's own hand (§10.4 step 2's fallback — a scope offender never gets a second applier). A second violation in the same round sends the whole round serial. Detected by diffing `git diff --name-only` against `applierAssignments` — never by trusting the applier's own `FILES:` line. |
| Parallel-applied round fails the union test (§10.4a step 4) | Revert **all** parallel-applied paths and re-apply the same findings serially per §10.4 steps 2–4 so the checkpoint attributes the regression. Record `serial-fallback r<N>`. Do not guess which fix broke it — guessing is what discards good fixes. |
| An applier (serial or parallel) returns `APPLIED: no`, fails, or makes no edit | Not an error: the applier is instructed to refuse rather than guess when a spec contradicts the code. The coordinator applies that one fix itself with its own context (§10.4 step 2's fallback); if the coordinator also cannot implement the spec, the finding is under-specified — record it as `FIX_FAILED` with the applier's reason. A refusal downgrades to coordinator-applied, never to skipped. |
| Serial applier edits outside its **owned** file set | Revert that applier's edits wholesale (owned paths plus the out-of-bounds paths) by restoring step 3's `preDispatchBlobs`, note `scope violation` in the round note, and re-apply that fix with the coordinator's own hand (§10.4 step 2's fallback — a scope offender never gets a second applier). Detected at step 3's **hard boundary**, which is the owned set from the fix spec, not the finding's cited set — the coordinator may have granted a wider set, and owned-but-uncited files are a soft-boundary `scope-expansion` flag, not a violation. **The comparison is against `git diff --name-only` minus `preDispatchPaths`, never the raw diff** — on the serial path the raw diff carries every earlier finding's paths, so a bare comparison convicts a blameless applier and reverts fixes that already passed their checkpoints. Same verify-don't-trust posture as §10.4a step 3. |
| A §10.4a precondition is unmet | Apply the round serially per §10.4 — which dispatches one applier per finding at every severity including CRITICAL *when a language specialist resolves*, one at a time with a checkpoint between, and is coordinator-applied otherwise (decision #81). This is the default path, not a failure — never relax a precondition to enable parallelism, and never let an applier assess its own eligibility. |
| Fix verifier returns `NOT_FIXED` (§10.4b) | Revert that finding's paths, record `FIX_FAILED`, defer to §10.7 with the verifier's REASON. **Do not retry** — editor and verifier disagree on what the finding asks for, which another edit cannot settle. |
| Fix verifier returns `PARTIAL` (§10.4b) — HIGH/MEDIUM | One retry with the verifier's reasoning appended; a second `PARTIAL` commits anyway and is deliberately left out of `priorFindingsFingerprints` so next round re-examines it. |
| Fix verifier returns `PARTIAL` (§10.4b) — CRITICAL | **Inverted by decision #71**, same as the unparseable-verdict rows below. Same one retry; a **second** `PARTIAL` does **not** commit — revert this finding's paths, record `FIX_FAILED (partial, unretried further)`, and defer to the final report. `FIX_FAILED` on a CRITICAL fires §10.6's stop. |
| Fix verifier agent fails or returns an unparseable verdict — HIGH/MEDIUM | **Same as the CRITICAL row below.** Re-dispatch the verifier once; if it fails again, revert this finding's paths, record `FIX_FAILED (unverified)`, count it in `fixVerifyTotals.unverified`, note `fix-unverified r<N>`, and continue the round. **The fix does not commit** (§10.4b). |
| Fix verifier agent fails or returns an unparseable verdict — CRITICAL | **Inverted by decision #71, bounded by #74.** Re-dispatch the verifier **once** — no verdict was rendered, so there is nothing to settle and the retry is free of `NOT_FIXED`'s objection. If it fails again: revert this finding's paths, record `FIX_FAILED (unverified)`, surface the CRITICAL unresolved in §10.7 — and **let the round continue** (§10.6's carve-out). The HIGH/MEDIUM row's "one more round is cheap" reasoning does not hold here, so the fix still does not commit; but a crashed agent is not evidence the CRITICAL is unfixable, so it does not stop the loop either. |
| Pre-commit hook fails on a loop commit | Fix the cause; reproduce with stderr non-TTY (`bash .githooks/pre-commit >/dev/null 2>&1; echo $?`), since a hook passing at a terminal can still fail under the harness. **Never** `git -c core.hooksPath=/dev/null` (§10.5 step 3) — the hook stops exactly the class of error an automated fix round is most likely to make. |
| Same finding fingerprint reappears after a claimed fix | STOP the loop and emit the "regression detected" report (§10.3 step 2 / §10.6) — a human-judgment moment, not a coordinator-fixable one. |
| Orchestrator subagent returns `DISPATCH-FAILED: Agent tool unavailable in subagent context` | Set `dispatch = inline`, re-run the review at §5A.1 in the caller's own context, and state in one line that orchestrator dispatch was unavailable. **Do not retry the dispatch** — a missing tool does not reappear. **Do not accept a report from that subagent**; a single agent role-playing the roster is the inline-fallback failure §12 names, and it must be surfaced, not absorbed. |
| Orchestrator returns `INCOMPLETE: <reason>` | Set `dispatch = inline` and re-run at §5A.1, stating the reason in one line. Do not retry the dispatch. |
| Orchestrator return says the reviewers are still running ("waiting on the remaining N", "notifications will arrive") | **Early return, not progress — nothing is waiting.** The orchestrator's turn has ended; its background children now notify the top-level session and it will not be re-invoked, so synthesis will never run. Re-run with `--inline` immediately. **Do not** wait for notifications, resume the subagent to ask if it is done, or hand-assemble a report from reviewer notifications that arrive later (that skips dedupe, the severity budget, and the report audit, and silently drops reviewers whose notifications never appeared). Root cause is **some** dispatch missing `run_in_background: false` — check the orchestrator dispatch (§5A.0) as well as the workers (§5A.4). The orchestrator call itself omitting the flag is the likelier culprit, precisely because it reads as "the run" rather than as a subagent. |
| Orchestrator return fails the §5A.0 integrity check: no `Wrote:` file holding `## Coverage Report`, and no full report in the return | Treat as a lost report (§5A.0). Say so explicitly and re-run with `--inline`. Never print such a return as the review, and never re-summarize it further to make it presentable. |
| `--inline` and `--in-subagent` both absent on a nested call | Cannot occur by construction — §5A.0's dispatch appends both. If a self-call is ever observed without them, that is the recursion guard failing: stop and report it rather than letting the dispatch loop. |
| Exactly one of `--inline` / `--in-subagent` present | **Behaves correctly — dispatch is an OR over the three tokens (§5.0 step 4), so either alone forces `inline`.** Do not hard-fail. Note it, though: the pair always travels together from §5A.0, so seeing exactly one means the args were hand-edited or a caller passed `--in-subagent` directly, and the latter is not a supported entry point. |
| `--refuters` outside 1–5, or not an integer | Parse-time hard-fail: `--refuters must be an integer 1-5 (got <v>)`. Above 5 there are no further lenses to assign (§5A.5a step 3) — the extras would cycle and vote as duplicates, inflating the majority denominator with correlated samples. |
| `--max-refuters` < 1, or not an integer | Parse-time hard-fail: `--max-refuters must be a positive integer (got <v>)`. |
| `--refuters` or `--max-refuters` passed **without** `--adversarial` | Parse-time hard-fail: `--refuters/--max-refuters tune the refutation stage, which is off by default; add --adversarial to enable it`. Silently ignoring them would let a caller believe refutation ran with their settings when it did not run at all. Do **not** treat these flags as implying `--adversarial`: inferring an expensive stage from a tuning flag is exactly the surprise the opt-in default exists to prevent. |
| `--adversarial` and `--no-adversarial` passed together | Parse-time hard-fail: `--adversarial and --no-adversarial are contradictory; pass one or neither`. Both silent resolutions are bad — honoring the enable silently bills a 4× run the caller half-asked not to have, and honoring the disable silently skips verification they half-asked for. |
| Refuter budget exceeded by CRITICAL groups alone | Run every CRITICAL group regardless and emit a stderr warning naming the overrun (`refuter budget <n> exceeded by CRITICAL groups alone; ran <p>`). A CRITICAL is never left UNVERIFIED to satisfy a budget — the budget bounds cost on nits, not on blockers. |
| Refuter agent fails or returns an unparseable verdict | Treat that refuter as `UNCERTAIN` (not-refuted) and continue with the remaining refuters for the group; note it in the group's verdict entry. **Do not re-dispatch** — a flaky refuter retried inline doubles cost on the exact claim least likely to resolve. If ALL refuters for a group fail, mark the group `UNVERIFIED` with the tag `_(unverified: all refuters failed)_` — **not** the budget tag — and render it in the Refuted Findings section's unverified subsection. |
| Every finding in the run is DROPPED | Emit the report normally with an empty Critical/High/Medium-Low set and a fully populated Refuted Findings section. Do **not** report this as a clean review — say explicitly in the Executive Summary that all findings were refuted, which is a signal about the *reviewers*, not about the code, and warrants re-running with a different roster. |
| Refutation produces a DROPPED CRITICAL | Never silently omit. Render it in full under Refuted Findings with every refuter's evidence, and state the count in the Executive Summary (§5A.5a step 4). In loop mode it does not trigger auto-fix but MUST appear in §10.7's refuted list. |
| Empty-coverage APPROVE (loop round) | Re-dispatch the round once with the unexamined load-bearing paths named (not counted as an iteration); if the re-dispatch again returns empty coverage, STOP with `STOPPED_NO_ENGAGEMENT` (§10.3 step 1). |
