# multi-agent-review — Flag reference

> Reference file for [`../SKILL.md`](../SKILL.md) (multi-agent-review). Load it before parsing arguments: §5.0 and §5A.1 parse "per §3", and this is §3's full table — which targets each flag is valid on, what hard-fails, and what the loop forwards to its inner passes.
> The `-h` table in SKILL.md is canonical for every flag's values and default. If this table disagrees, the `-h` table wins; fix this file. `../scripts/check_flag_tables.py` fails when the two tables list different flags.

## 3. Invocation grammar — per-flag reference

```
multi-agent-review <target-type> <target-args...> [flags]
```

| Position / flag | Required | Valid on | Values |
|---|---|---|---|
| `<target-type>` (positional 1) | yes | — | `pr` \| `dir` \| `file` \| `spec` \| `diff` \| `slices` |
| `<target-args>` (positional 2..N) | yes | — | per type: PR number/URL; directory path; one file path; one or more markdown paths; (none for `diff`); two or more directory paths for `slices` |
| `--reviewers <csv>` | no | all targets | comma-separated agent names; default = the generic roster (see §4). Validated at parse time (§5A.1): whitespace around commas is stripped; unknown names hard-fail before any agent is spawned. In loop mode, forwarded to each inner review pass. |
| `--synthesizer <name>` | no | all targets | single agent name; default = `knowledge-synthesizer`. Validated at parse time (§5A.1) against the same agent union as `--reviewers`. In loop mode, forwarded to each inner review pass. |
| `--write-to <path>` | no | all targets | explicit path override for the report file; resolved relative to `git rev-parse --show-toplevel` when not absolute. Does **not** control whether a file is written — that is on by default (see `--no-write`). A tracked path is the rare, explicit opt-in for committing a report; the default is git-ignored. In loop mode, writes **once** — the final loop report — not once per round. |
| `--no-write` | no | all targets | suppress the report file; print to stdout only. The report is otherwise written by default to the git-ignored `.claude/reviews/<YYYY-MM-DD>-<slug>.md` in the primary checkout (§5A.1 step 10) — pass this for a throwaway read. Mutually exclusive with `--write-to`; passing both is a parse-time hard-fail. Does not suppress the PR comment (see `--no-comment`). In loop mode, forced on for every inner pass regardless of the caller's choice. |
| `--no-comment` | no | `pr` target | skip the PR comment. A `pr` target otherwise posts exactly one comment carrying the report (§5A.7 one-shot, §10.7 loop), independent of whether a file was written. No-op on non-`pr` targets. |
| `--force` | no | all targets | with `--write-to`, allow overwriting an existing file. Not needed for the default path, which suffixes `-2` instead. |
| `--max-files <n>` | no | `dir`, `slices` | override the directory file-count cap (default 50; per slice on `slices`) |
| `--max-slices <n>` | no | `slices` | override the `slices` per-invocation slice cap (default 6). Each slice spawns its own roster, so total reviewer agents = `len(roster) × len(slices) + 1` synthesizer; the cap prevents runaway agent fan-out. |
| `--staged` | no | `diff` | only valid with `diff`; resolve materials from `git diff --staged` (staged-but-uncommitted hunks) instead of the working-tree `git diff`. |
| `--mode <name>` | no | all targets | named preset that supplies the default reviewer roster and (optionally) the synthesizer. Presets live in `.claude/multi-agent-review-modes/<name>.md` (project) or `<plugin-install-root>/modes/<name>.md` (user); project shadows user by filename. Explicit `--reviewers` / `--synthesizer` still win. In loop mode, forwarded to each inner review pass. |
| `--prompt-prelude <path>` | no | all targets | path to a markdown/text file whose contents are prepended to every reviewer brief (and the refuter and synthesizer briefs) under a `## PROJECT PRELUDE` section. Used for project-defined skip-lists (e.g., "do not re-raise findings already tracked in issues #82/#83/#84"), house-style notes, or terminology glossaries. Resolved relative to `git rev-parse --show-toplevel` when not absolute; missing file = hard-fail before any agent is spawned. Size capped at 16 KB; larger files = hard-fail with the size + cap. In loop mode, forwarded verbatim to round 1 and embedded at the top of the state-rendered prelude from round 2 onward (§10.2 step 0), so the caller's skip-list reaches every round. |
| `--lenses <csv>` | no | all targets except a looping `pr` | comma-separated reasoning-model slugs, each dispatched as its own `general-purpose` reviewer slot **additive to** the roster (never replacing it). Valid slugs: `pre-mortem`, `inversion`, `first-principles`, `red-team`, `jobs-to-be-done`. Directive text comes from `refs/multi-agent/reasoning-lenses.md`. Whitespace around commas is stripped; unknown slugs and duplicates hard-fail at parse time (§5A.1); at most 5. When non-empty, the steel-man stance is injected into **every** brief under `## REASONING STANCE` (§7) — including the ordinary code reviewers. **Hard-fails at parse time on a looping `pr` target** (§5.0 step 3b) — pass `--no-loop` to use it there; it is unrestricted on `pr --no-loop` and on every other target, so this row is NOT "forwarded to each inner review pass" the way other flags are (there is no loop invocation left for it to reach). On a non-document target (`diff`, `dir`, `slices`), each lens directive's "spec" is read as the change or code under review rather than a document; `file`/`spec` remain the intended primary use. |
| `--high-cap <n\|off>` | no | one-shot runs | cross-axis severity budget for HIGH findings (see `refs/multi-agent/fanout-consolidation.md`). Default `8`. The synthesizer demotes HIGH findings beyond `min(cap, ceil(N_reviewers * 1.5))` to MEDIUM. Set `off` to suppress the budget entirely — required when this skill is used as a per-phase gate by an upstream pipeline that derives `VERDICT = CLEAN iff zero CRITICAL+HIGH`; demotion in that context would silently let unresolved HIGHs through. The same holds for a one-shot `spec`, `diff` or `dir` review the caller treats as a phase gate. The skill cannot tell a gate from a report, so the caller passes `off` and the skill applies whatever cap it receives (§5.0 step 3c). For one-shot PR/audit reviews that gate nothing, leave at default. Any summary or handoff built from a capped report lists each demoted finding at its original severity, from the orchestrator's `Demoted:` line (§7c). **In loop mode this flag is NOT forwarded — the loop forces `--high-cap off` on every inner review pass** (see §4); an explicit `--high-cap <n>` on a looping `pr` target triggers a warning that it is overridden to `off`. |
| `--inline` | no | one-shot runs | run the review in the caller's own context instead of dispatching an orchestrator subagent (the original behavior). Accepted no-op on a looping `pr` target, whose coordinator is always inline. Use to watch the fan-out, or after a `DISPATCH-FAILED` / `INCOMPLETE:` / early return (§5A.0). |
| `--in-subagent` | **internal / reserved** | §5A.0's dispatch only | Not for end users. Passed by the orchestrator dispatch alongside `--inline`; §5.0 step 4 reads it from its own `args` and forces `inline` when present — the parser-visible recursion backstop behind `--inline`, mirroring `--in-loop`'s role behind `--no-loop`. |
| `--no-report-audit` | no | all targets | skip the report adversary stage (§5A.6a), which is otherwise **on**. That stage is one agent that audits the finished report against the reviewer outputs and refutation verdicts; it does not attack findings and adds no cost that scales with finding count. Skip it for a fast smoke-read. In loop mode, forwarded to each inner review pass. |
| `--adversarial` | no | all targets | **enable** the adversarial refutation stage (§5A.5a); findings are attacked by independent refuters before synthesis. **Off by default** — see "Why it is opt-in" in `references/adversarial-rationale.md` for the cost measurements and when it pays. In loop mode, forwarded to each inner review pass. |
| `--no-adversarial` | no | all targets | accepted **no-op**, retained for back-compat with older invocations and scripts. Refutation is already off unless `--adversarial` is passed, so this flag now only restates the default. Combining it with `--adversarial` is a parse-time hard-fail (§11) — the intent is ambiguous, and guessing either way silently bills or silently skips. |
| `--refuters <n>` | no | all targets | refuters per CRITICAL/HIGH finding; integer 1–5, default `3`. MEDIUM/LOW always get `2` (§4) and are unaffected by this flag. At `--refuters 1` no finding can ever be DROPPED — the drop threshold has a floor of two, so a lone refuter can only mark a finding CONTESTED (§5A.5a step 4). **Requires `--adversarial`**; passing it alone is a parse-time hard-fail (§11). In loop mode, forwarded to each inner review pass. |
| `--max-refuters <n>` | no | all targets | total refuter-agent budget for the run; integer ≥ 1, default `20`. When the computed fanout exceeds it, refutation degrades lowest-severity-first (LOW → MEDIUM → HIGH; CRITICAL is never skipped) and every skipped finding is reported as `UNVERIFIED` — never silently dropped from verification (§5A.5a step 2). **A finding-rich review will exceed 20 and leave a visible `UNVERIFIED` tail** — that is the intended trade (see #50), and raising the flag is the remedy when a run needs full coverage. **Requires `--adversarial`**; passing it alone is a parse-time hard-fail (§11). Note the budget is **per review pass, not per session** — a looping `pr` run forwards it to every round, so an `N`-round loop can dispatch up to `N × --max-refuters` refuters in total. In loop mode, forwarded to each inner review pass. |
| `--no-loop` | no | all; meaningful only on `pr` | forces a one-shot read-only report on a `pr` target (the original default); accepted **no-op** on every other target (documented so uniform scripting doesn't break). Mutually exclusive with the loop-only flags (`--max-iterations`, `--resume-stopped`, `--high-and-up-only`, `--no-smoke`) — combining them is a parse-time hard-fail; `--yes` is a no-op instead. |
| `--yes` | no | looping `pr` only | skips the confirmation gate (§5.0) for unattended/automated runs — the only way to loop without the interactive prompt. No-op on non-`pr` targets and on `--no-loop` runs. |
| `--in-loop` | **internal / reserved** | loop's inner self-call only | Not for end users. Passed by the loop coordinator to each fresh-subagent review pass; §5.0 reads it from its own `args` and hard-refuses loop mode (forces one-shot) when present — the parser-visible recursion backstop behind `--no-loop`. |
| `--max-iterations <n>` | no | looping `pr` only | integer 1–8, **default 1**. Parse-time hard-fail when combined with `--no-loop` or a non-`pr` target. |
| `--resume-stopped` | no | looping `pr` only | resume a checkpoint left on a `STOPPED_*` safety stop (§10.6). Off by default: that state exists to get a human's judgment, so the flag asserts the judgment was made. The coordinator passes it to `loop_state.py check` and nowhere else — it never reaches a review pass or an applier. Parse-time hard-fail with `--no-loop` or a non-`pr` target. |
| `--high-and-up-only` | no | looping `pr` only | coordinator auto-defers MEDIUM/LOW each round; only CRITICAL + HIGH drive iteration. Parse-time hard-fail with `--no-loop` or non-`pr`. |
| `--no-smoke` | no | looping `pr` only | skip the live smoke test on a round even when connector/runtime code changed. Parse-time hard-fail with `--no-loop` or non-`pr`. |
