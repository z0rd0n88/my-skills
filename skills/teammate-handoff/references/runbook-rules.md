# Runbook rules

Every rule here is a defect an unattended run hit or a critique caught on the 2026-11-04 sign-in
stack runbook (VistaMarkets/Flutter-mobile-app PRs 73 to 80, eight critique rounds). A new runbook
carries every rule from its first draft, so the critique loop finds new defects instead of these.
The critique prompt cites rules by id; `scripts/check-runbook.sh` checks the mechanical ones.

The executor is a Claude Code session with permission prompts off, no human watching, no custom
skills, no browser.

## A. The harness the executor runs in

| Id | Rule | Defect it prevents |
|---|---|---|
| A1 | The launch line is `BASH_DEFAULT_TIMEOUT_MS=1800000 BASH_MAX_TIMEOUT_MS=1800000 claude --dangerously-skip-permissions`, and the runbook says why: the Bash tool's foreground timeout is two minutes by default. | A gate longer than two minutes was cut off before its verdict line; the "two fix attempts" rule then chased a phantom failure. |
| A2 | A call that reaches the timeout is moved to the background and keeps running. The runbook says, for every long command: never start it again while it runs; read the Bash tool's own output file (the path the moved-to-background result names, not the tool's per-check logs) until the verdict line; wait with one `sleep` call shorter than the foreground timeout, then read; 30 minutes after the move, stop the task with `TaskStop` and the task id from that result, run once more; a second miss is a finding with a destination step, never another retry. | "Run it again" started a second build beside the first on one simulator and one checkout and truncated the shared log. "If the file stops growing" was undecidable because the gate writes each check to its own log and the Bash file stays quiet for the whole test run. |
| A3 | The Bash tool is not a TTY. `gh pr merge`, `gh pr review --approve` and every `gh` tick line print only to a terminal. An Expected never names TTY-only output. Every step is decided by a probe whose output shape was run live and pasted: `gh pr view PR --json state,mergeCommit --jq '"\(.state) \(.mergeCommit.oid)"'` prints `MERGED <sha>`; `gh pr view PR --json isDraft,reviews --jq '"draft=\(.isDraft) approvals=\([.reviews[]|select(.state=="APPROVED")]|length)"'` prints `draft=false approvals=1` (the inner quotes are plain inside a jq interpolation; `\"` fails to parse on gh 2.101.0). | The merge step expected a tick line that cannot appear, so a literal executor read silence as a CLI error, ran the REST fallback on a merged PR, got 405 and stopped falsely. |
| A4 | With the head branch checked out in the primary clone, `gh pr merge --delete-branch` switches the clone to the base branch and fast-forwards it; git prints `Switched to branch`, `Updating`, `Fast-forward` and a diffstat. From a linked worktree it warns, skips the local delete and exits 0. The Expected describes the output for the case the runbook is in and says where the clone sits afterwards. | "Exit 0 and no output" gave the real case, exit 0 with git output, no branch to follow. |
| A5 | `gh api --jq .field` prints an empty line for a missing key, not `null`. Probe with `.field == null`, which prints `true` or `false`. | A stack probe written as `--jq .stack` printed nothing on every PR and the Expected `null` was never met. |
| A6 | Every `git commit` and `git merge` in the runbook carries `--no-edit` or `-m <msg>`; every `git revert` carries `--no-edit` (its `-m` is the mainline parent, not a message). | A bare commit opened an editor and hung to the timeout. |
| A7 | `grep -c` exits 1 on zero matches: append `\|\| true` to every `grep -c`. A pipe into `tee` hides the exit code of the command before it: add a positive grep whose Expected is `1`; it carries `\|\| true` too, and its Expected `1` still decides. | A build failure printed `0` exceptions and read as a pass; a zero count read as a failed command. |
| A8 | `gh pr list` carries `--limit 100`. | The default 30 rows hid PRs once the repo had more open. |
| A9 | The paste prompt runs `git fetch --prune origin` before anything else. | A branch deleted by a merge stayed in the clone and a stale copy of the runbook was served. |
| A10 | The paste prompt reads the runbook with `git show origin/<docs-branch>:<path>`, switches to `origin/<default>` when the docs PR is `MERGED` (decided by `gh pr view N --json state --jq .state`), and re-reads it after every checkout. | The run died before setup when the docs branch was gone. |
| A11 | No step needs a browser or a web page. | A web-page merge fallback that an unattended executor cannot perform. |
| A12 | The target repo's tracked Claude hooks (`.claude/settings.json` and what it loads) run on the teammate's plain Claude Code too. The author reads them in Phase 2; a hook that forbids edits outside a worktree, refuses a git command, or runs a build on Stop shapes the loop (a per-piece worktree, a different command, no turn ending mid-build), and the runbook says which hook each shape answers. | A loop written for a bare clone that the repo's own worktree guard refuses on the first edit. |

## B. Resumability: state lives on the remote

| Id | Rule | Defect it prevents |
|---|---|---|
| B1 | A relaunch is any run after a crash or after the owner cleared a stop. The runbook says so once, where setup begins, and every "relaunch" sentence means both. | A reader applied "after a crash" text to a crash only and had no rule for the cleared stop. |
| B2 | Setup's first command tolerates a dirty tree: `git merge --abort` when `git status` reports unmerged paths; `git stash push -u -m <tag> -- <paths>` for crashed edits, with a pathspec that keeps the ledger out of the stash. | A crash mid-conflict blocked `git checkout main` on relaunch and no step said to abort; a bare `stash -u` swept the ledger away. |
| B3 | Where the run starts is read from GitHub, never from a file on disk: one probe per piece for `state`, `isDraft`, `mergedAt`, then approvals. Every `MERGED` piece is skipped with its bookkeeping backfilled; the first `OPEN` piece starts; `draft=false` with `approvals=0` means the approve never landed, so approve, then merge; `CLOSED` with `mergedAt` null, or `MERGED` above an `OPEN` piece, is a stop. | The first draft stopped on any relaunch past the first merge because setup expected every PR to still be a draft. |
| B4 | Every list, loop and Expected holds on five relaunch paths, and the runbook walks them in its text: fresh run; after a merge with bookkeeping done; crash between merge and bookkeeping; crash between approve and merge; fresh clone. A loop over branches guards each ref (`git rev-parse -q --verify <ref> >/dev/null \|\| { echo merged; continue; }`) because a merged branch is gone. Setup Expecteds admit the resumed state: merged pieces absent from listings, the first open piece based on the default branch, `draft=false`. | A `merge-tree` loop over all branches errored on the deleted one and printed `not clean`; a setup Expected written for the fresh run stopped every relaunch before the resume check ran. |
| B5 | A stale base (the next PR still targeting a deleted head branch) is repaired in the loop's first step with `gh pr edit PR --base <default>`, not only in the bookkeeping step a resume skips. | A crash between merge and bookkeeping left the next piece pointed at a dead branch with no remedy on its path. |
| B6 | The ledger is an untracked file in the clone, never under `/tmp` and never committed. Its rows are written by a header-first rule, `test -f <ledger> \|\| printf '<header>' > <ledger>` then the row; a backfilled row takes its cells from that PR's review comment (`gh pr view PR --comments`); the merge sha comes from `gh pr view PR --json mergeCommit --jq .mergeCommit.oid`, never from the branch tip. It is the record for the final report, never resume state. | A fresh clone appended rows to a file with no header and the final report was a headerless table; backfilled rows carried unfilled `<...>` cells with no named source; a row read from `git rev-parse origin/<default>` names a later push when one lands before the row is written. |
| B7 | Counters (fix attempts, base moved) live only in the model's context; the PR comments are the durable count, so every repeat posts a follow-up comment on the piece's PR. | A 13-hour session could not prove how many times a bound had been hit. |

## C. Stop and bound everything

| Id | Rule | Defect it prevents |
|---|---|---|
| C1 | Every stop condition is decidable by a command whose Expected is shown. The stop list and the body state each rule identically, or one points at the other by its heading. A stop posts a comment on the delivery PR: piece, condition, exact output. | Two sections stated one rule two ways and the executor had to pick. |
| C2 | Every retry is bounded and the bound covers every check step, not only the gate: two fix attempts per check; a fixed number of re-runs of an `UNKNOWN` mergeable state; the third "base moved" on one piece; one retry after a timeout. | The smoke step cycled through fix and re-run with no cap because the cap said "a gate check". |
| C3 | Revert-and-stop, never revert-and-continue, and revert only while the base's tip is still the merge being blamed (`git rev-parse origin/<default>` equals that PR's `mergeCommit.oid`); if the base moved past it, stop without reverting. The runbook says why: reverted commits still sit in the branches above and return at the next merge-in. | A fix patched forward on top of a broken default branch; a later variant reverted an innocent merge. |
| C4 | Before every merge: `git fetch origin && git merge-base --is-ancestor origin/<default> HEAD`. On a move, repeat from the merge-in step and post the new gate output as a follow-up comment. | A merge landed against a base the gate had not seen. |
| C5 | A merge conflict is resolved only when self-inflicted. The decider runs while the merge is in progress: `git log --no-merges --format=%s "$(git merge-base HEAD origin/<default>)"..origin/<default> -- $(git diff --name-only --diff-filter=U) \| grep -v '^<prefix>'`. Nothing printed: resolve by hand, `git add`, `git commit --no-edit`, re-run every check step, push. Anything printed: `git merge --abort` and stop. Every commit the run makes carries the prefix, test-only commits included, and no commit on the default branch since the stack branched uses it: `git log --format=%s "$(git merge-base origin/<first piece branch> origin/<default>)"..origin/<default> \| grep -c '^<prefix>' \|\| true` prints `0`. | One ordinary fix on a file every piece touches ended the run at the next piece; a `test:` commit made a self-inflicted conflict look foreign. |
| C6 | The approver is not the author: `gh api user --jq .login` beside the launch line, repeated before setup, must not print the author's login. Push access is proved by `gh api repos/<owner>/<repo> --jq .permissions.push` printing `true`; `gh auth status` cannot show it. | A box signed in as the author could not approve and nothing stopped it; a read-only collaborator passed setup and died at the first push. |
| C7 | Approve before marking ready, so a crash between them cannot merge unapproved; the resume path re-checks approvals (B3), which is what allows the draft fallback (ready, then approve, when the approve errors on a draft). | A fallback that reversed the order (ready, then approve) opened a window a resume rule without the approvals re-check read as "already approved". |
| C8 | When piece N+1's gate fails after a clean merge-in: gate the default branch first. Green: fix on N+1 as a finding. Red while the tip is still N's merge: C3. | Patch-forward with no revert path. |
| C9 | The fallback merge (`gh api -X PUT repos/<owner>/<repo>/pulls/PR/merge -f merge_method=merge`) covers a CLI error only. It leaves the head branch, so the runbook deletes it with `git push origin --delete BRANCH`. A refusal that the PR is part of a GitHub stack is a stop, and setup probes `.stack == null` on every PR first. | The fallback was offered for the one failure it cannot handle, and a stack refusal would have been retried. |
| C10 | Every finding has a destination step. A finding about something under "Not this job" is a comment, not a fix. | A smoke failure had no step to go to; a CRITICAL finding tempted a fix the owner had excluded. |

## D. Writing rules

| Id | Rule | Defect it prevents |
|---|---|---|
| D1 | Counts go stale, commands do not. Never write a number the runner could compute (commits on the default branch, test counts); write the command and its Expected. A count is a floor: it may grow, never shrink. | "Main has moved 5 commits" was wrong by the time the runbook was committed; a fixed root-test count read a new test on the default branch as a finding. |
| D2 | One rule, stated once. A rule that appears in two sections reads identically or one points at the other by its exact heading. | The conflict rule contradicted itself across two sections. |
| D3 | Every placeholder used in a command is defined in the one sentence that begins "Substitute before running:", and that sentence also says to fill every `<...>` cell before running. A placeholder with lookalikes on its line is defined by its shape (the simulator UDID is the hyphenated 36-character value; the last parenthesised value is the boot state). | `NEXT_PR` was used and never defined; "the value in parentheses" picked `Shutdown` on a line with two. |
| D4 | Every command block is followed by an Expected block giving the real output shape, run live on the authoring box and pasted in full (every header line the tool prints, not an abridged version). A command the authoring box cannot run is marked "verified from source and docs, not run" and listed under Unverified in the teammate handoff. | An abridged gate Expected never matched the real output; a `flutter --version` Expected named a first line that an upgrade banner displaces. |
| D5 | Every path is written in full from the repo root. A bare file name is allowed only where the runbook states the prefix once and the check script proves the name resolves to one file. | Two files were named in a directory they do not live in; two bare paths did not exist on the default branch. |
| D6 | A step that re-runs other steps names every one of them. A step inserted between two numbers (3b) is named in every list that spans it. | "Re-run steps 2 and 3" let a fix to a screen merge without a fresh simulator pass. |
| D7 | Every pointer names its target's exact heading. | "see If something goes wrong" pointed at a rule whose heading had changed. |
| D8 | Platform-specific steps are isolated, named, and wrapped in `<!-- platform: <os> -->` and `<!-- /platform -->` markers (`mac`, `linux`), with their tool checks in setup wrapped the same way. The executor's platform decides at each marker: a step for its own platform runs; a step for another platform is skipped with the waiver recorded in the piece's review comment, or replaced by its equivalent on the executor's platform (an Android emulator smoke for an iOS simulator smoke; a gate's own Gradle line plus CI checks for a Linux-only gate script), written beside it inside the executor's own markers. This version builds the Mac executor; Linux is the next; Windows is out of scope and the same markers are its seam. | Mac-only steps mixed into shared steps cannot be ported or waived without a rewrite. |
| D9 | The repo's own gate script and guard script are read line by line before the runbook names their output; the runbook uses them as they exist on the default branch and invents no second gate. | An Expected that described what the author assumed a script printed. |
| D10 | House style of the target repo holds in the runbook: no em or en dashes, sentence-case headings, the repo's commit-subject convention. | Style findings that cost a critique round. |
| D11 | Every untracked file a command reads (a `--body-file`, a log, a scratch file) is written by an earlier step in the runbook. | A comment was posted with `--body-file /tmp/review-PR.md`, a file no step wrote. |
| D12 | The target repo's always-loaded rules (`AGENTS.md` or `CLAUDE.md`, a constraints file) hold in the runbook: each verify-before-claiming convention they state is a step or a named waiver under "Not this job". | `AGENTS.md` asked for a simulator run on visual changes; the runbook had no smoke step and no waiver. |
